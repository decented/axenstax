Engineering
roadmap.

Where the project stands, what is waiting on people and real devices, and what comes later. As of 2 October 2026: native release v0.2.27, network protocol v64. The full roadmap lives on the docs site; this is the short version.

Where we are

An open-source, self-hostable voxel sandbox with its own engine, client and server, written in Rust. The build queue is empty: everything that was ready to build has been built. What is left is work that needs a person or a real device, and a short list of design decisions.

Web: a taster

The browser game at play.axenstax.com is an anonymous, local-only sandbox. No login, no multiplayer, no cloud save. Worlds live in your browser and can be exported to the desktop app.

Native: the full game

The Linux AppImage has Signet sign-in, LAN play, online play by contact, the dedicated server and the feedback mailbox. Windows and macOS installers are not published yet; both build from source.

Parked

Android is proven on hardware but nothing is published. Gamepad support is built and working, but is not a launch priority.

Posture

Self-hosted, sovereign, player-owned. Worlds, saves and identity belong to the player. AxeNStax ships software, not a service.

Shipped

Implemented and in the current build. The long version is on Built.

Engine and rendering

A custom Rust engine on wgpu, native and WebAssembly from one codebase. Greedy meshing, day and night, weather, water and lava flow, lighting, particles, resolution-agnostic texture packs with hot-swap, and a single regression gate that covers lint, tests, the web build and a bundle-size limit.

World and gameplay

Survival and creative, crafting and smelting, farming and fishing, armour, hunger, biomes, caves, ravines, villages and a full ore set. Electricity with wires, batteries, lamps, a windmill and a water wheel. Timed Trials, slash commands and an optional guided companion.

Creatures

A broad mob roster, tameable pets and steeds, bees, animal genetics and breeding, and a racing animal. Mob AI, spawning and physics run server-side, with changes sent to joiners.

Building and creative tools

Stairs, slabs, doors, panes and signs; schematics with a build guide; the Workshop and Rig Studio for reskinning blocks and mobs; a skin editor with Minecraft import and export; exhibits and a kiosk mode; rails and cables; an opt-in third-person view; and a one-file export that carries your web worlds into the desktop app.

Multiplayer and identity

LAN co-op, split-screen and a headless dedicated server with an Operator Console. Online play by contact: join a friend's home-hosted world by their Signet persona or an invite. Relays carry connection setup only, then the connection is direct and strangers get silence. World chat is native-only. Signet QR sign-in and contacts sync are in. An operator can publish their own server through an opt-in Nostr announce; nothing is ever announced automatically.

Sites and distribution

Six public sites. A Linux AppImage with an in-place updater, a cross-platform packaging pipeline, and player documentation: wiki, learn journey, tutorials and operator guides.

Privacy by construction

The web build has no login, cookies, analytics or feedback channel, and the site apps do not log IP addresses. Native feedback is per-report burner key, end-to-end encrypted, with no replies. Saves are crash-safe. Proof of Play is an educational proof-of-work primitive, never an earning mechanic.

Now: waiting on people and devices

Each of these needs a second machine, a real device or a decision that is not the code's to make.

Live tests

Two-machine LAN play with a real remote signer, and online play by contact across two real homes. Contacts sync and QR sign-in on a phone. Death drops and late-joiner backfill with a second player, the unverified Trials, an electricity switch test across two machines, and first launch of the data migration and updater on real hardware.

Fun test

Play-testing with volunteer children who are not family. Family play has been a bug hunt, not evidence that the game is fun, so fun is still unvalidated.

Before the source goes public

Sign-off of the draft privacy page and the Children's Code posture, a fresh public repository, and README and credits polish. Sign-in, pairing and feedback already default to decentralised public relays, with one relay list players can edit before they connect; the phone tests are pending.

Release

Native v0.2.27 is cut once the repository is public. Until then the published installer is older than the source.

Next: design calls

Only the items that block building further on top of the current foundations.

Late-joiner chunk streaming

Entities already backfill at join. World edits and chunks for a late joiner need a call between edit-log replay and chunk push; multiplayer chunk compression rides on the same decision. Anti-X-ray chunk obfuscation is built and tested but not yet in the live send path; it lands with this.

One simulation, not two

Single-player still runs its own mob and falling-block simulation beside the server's. The fix is to route single-player through a local server, which needs a playtest with the client-side sim removed. The same change settles the host's own position trust.

Server-authoritative saving

The save path and the client use two overlapping player structures that will drift. They unify when saving becomes server-authoritative.

Identity and chat boundaries

The signed identity is authoritative and the typed join name is a display fallback only; what remains is live two-machine verification. The chat ceiling can only be lowered locally; raising it waits on a real capability boundary.

Two owner decisions

The final merge policy when an imported world's name clashes with an existing one (today both are kept), and how sub-block detail for high-resolution statues and faces should work.

Later

Horizons. None of these is scheduled and none is built unless it says so.

Deeper systems

An eight-tier farming economy. Player-driven economies on the settled non-custodial model (the engine holds a score, never a balance). Rail logistics phases 2 to 4. Electricity phases 3 and 4. A wireless-signalling element, designed but not built.

Worlds and creators

Multi-world places with a hub and portals on one self-hosted address. Creator gallery phases 3 and 4. Cinematic camera and replay, partly built and not yet verified end to end. The Genesis founding-myth storyline.

Play and access

Voice and proximity audio (not built). Guardian-facing controls: the operator allowlist exists, a guardian surface does not. A companion screen, networked spectator tiers, and non-custodial, bring-your-own-key cloud save on native.

Platforms and tooling

Windows and macOS installers and an Android release. Small-box hardware targets and GPU-tier auto-detect. Self-hosting tooling such as backups and per-world configuration. Texture-pack distribution and WASM plugins for sandboxed server-side mods.

A Bitcoin-enabled server layer

Design only, and nothing is switched on. It would have to follow the rules below: off by default, parent-controlled, set per server, and driven by a deterministic work-meter.

Out of scope: red lines

The project does not and will not do these. They keep AxeNStax a software vendor, never the operator of a service.

No directory, no game servers

No public directory of player-run servers, worlds or groups. Discovery is LAN-local, direct-address, or an operator's own opt-in announce. No game servers, and no relays carrying a group's game traffic, presence or chat. Multiplayer runs directly between players.

No central child data

No central collection of children's data and no collection of age as raw data. The web taster stays anonymous and local; feedback is burner-key and end-to-end encrypted.

A building game

Not positioned or marketed as a social network, social media or a chat platform. Playing with friends means building together.

No chance-based payouts

Proof of Play is educational proof-of-work. Any real-money layer is off by default, parent-controlled and per server, with a deterministic work-meter and never a probabilistic threshold. And no how-to for turning safety off: sensitive features sit behind a real capability boundary, not a disclaimer.

Retired

The original plan for a paid hosting fleet, matchmaking, platform services and celebrity-scale events is retired. It would make AxeNStax the operator of the service, which these lines exist to prevent.
