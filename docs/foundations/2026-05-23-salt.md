# Salt — mining, husbandry, preservation, path-salt, lamps

**Status:** Phases 2–10 DELIVERED 2026-05-23 on `feat/salt`. Phase 11 = Axolittle playtest gate (open).
**Branch:** `feat/salt` off `main`.
**Trigger:** Axolittle's call (2026-05-23): salt as a mineable material with five concrete in-game uses — flavour enhancer, food preserver, animal husbandry via salt licks, path de-icer (snowfall prevention), and decorative salt lamps as light sources.

---

## TL;DR

One cohesive Salt feature ships five interlocking sub-features:

1. **Mining source** — new `ROCK_SALT` ore in Mountains + Desert biomes drops 1–2 `Salt` material.
2. **Flavour + preservation** — Salt-Cured X (raw meats) and Seasoned X (cooked foods) recipes lift `food_value` by +1 per upgrade tier.
3. **Salt Lick block** — placed by player; livestock within 8 blocks regen 2× HP and drop +1 of their primary product on kill; nearby livestock steer gently toward the lick when wandering.
4. **Salt Path + minimal snowfall layer** — right-click Salt on dirt/grass/snow places a visible `SALT_PATH` block (clears existing snow and prevents new accumulation); a slow random-tick snowfall painter places `SNOW` on dirt/grass tops in `SnowyTundra` chunks, naturally skipping `SALT_PATH`.
5. **Salt Lamp block** — torch-equivalent light source (`light_emission = 14`) with a warm amber procedural texture; floor-only placement; pure decoration, no block-entity.

Plus a `SALT_BLOCK` 9-salt storage block (matches the existing `IronBlock`/`SugarBlock` storage convention).

5 new BlockIds (115–119), 16 new MaterialIds (`Salt` + 6 Cured-X + 9 Seasoned-X), 19 new recipes, 2 new modules (`salt_lick.rs`, `snowfall.rs`) holding the pure helpers, ~2 000 LOC including tests. PROTOCOL_VERSION 28 → 29 (BlockId additions only — save-format extension via positional `u16` enum append).

Independent of every open spec — no shared files with Specs 1 (engine Signet auth) or 2 (HostedServer routing). Parallelisable with anything currently in flight.

---

## Why this lives here

- **Bridges two long-run vision rows.** Farming T2 calls for animal husbandry mechanics (breeding, draft animals); Spec 6 / cross-economy vision calls for food-quality tiers. Salt is the first material that gates BOTH lanes — without it, husbandry has no input and food has no value ladder. Cheap to ship now.
- **Pulls SnowyTundra biome from "decorative" to "interactive".** The biome currently has no gameplay role beyond cold-tinted terrain. The minimal snowfall layer + salt-path interaction give kids a visible reason to visit a snowy zone and a visible consequence of using salt.
- **Lifts cross-game.** "Aura block influences nearby mobs" (Salt Lick) is engine-generic — the same shape lifts to another game's burrow-keeping mechanic and another game's egg-laying. "Place-blocks-to-suppress-environment-effect" (Salt Path → Snow) is a generic pattern any survival game wants.
- **Foundation for v2 economies.** Cured/Seasoned variants slot into Vendor Block trades immediately at higher trade_value than raw produce — first taste of a flavour-tier-priced market without needing new vendor infrastructure.

|---|---|---|---|---|---|
| 115 | `ROCK_SALT` | Yes | No | No | Ore. Mines with `Stone+` pickaxe via the existing tool-tier gate. Drops 1–2 `Salt` per strike (per-position seeded). Generates in `Mountains` + `Desert` biomes between y = 60 and the local surface, in vein-of-3-to-6 clusters via the existing `biome::base_rock_at` decoration pass. |
| 116 | `SALT_LICK` | Yes | No | No | Decorative aura block. 8-block radius livestock effect (see §3). Mines with shovel; drops the block itself. |

Each block has a procedural texture in `texture_gen.rs`:

- `ROCK_SALT` — pale stone base + white-pink crystalline veins (saturation ~0.7).
- `SALT_LICK` — chunky off-white cube with greenish-brown mineral inclusions (looks like the bovine-mineral-block reference).
- `SALT_LAMP` — amber/pink crystal cluster with a faint glow halo painted in (no shader work; just the texture sells the "lit" feel).
- `SALT_BLOCK` — solid white-pink, fine crystal grain.
- `SALT_PATH` — dirt base with white salt-crystal sprinkle on top half of every face (top face heaviest sprinkle; visually distinct from grass + dirt).

### 2. One new `MaterialId`

`Salt`, slotted next free after the historical-pivot additions. UK English label "Salt". Procedural item-sprite: white-pink crystalline grain on a dark backdrop.

### 3. Salt Lick — animal husbandry mechanic

New module `salt_lick.rs` holding pure helpers + a tick driver.

**Aura radius:** 8 blocks (Chebyshev, like the bee-hive nectar gate). Affected `MobType`s: `Cow`, `Sheep`, `Horse`, `Pig`, `Goat`. Carnivores (Wolf, Bear, Hyena) and exotics (Bee, Squid, Nostrich, Rabbit, Chicken) are explicitly excluded for v1 — the lick is "livestock infrastructure".

**Per-tick effect for affected mobs within aura:**

- **HP regen 2× normal rate.** The existing per-mob regen tick reads from a new `regen_multiplier_at_pos(world, pos) -> f32` pure helper that returns `2.0` if any `SALT_LICK` is within 8 blocks Chebyshev, else `1.0`. No new save state.
- **Steering bias.** While in `AiState::Wander`, the chosen wander direction biases 25 % toward the nearest `SALT_LICK` if within 16 blocks Chebyshev (a gentle pull, not pathfinding). Pure helper `wander_bias_for_salt_lick(mob_pos, ...)`.
- **Drop bonus.** On kill, the existing `drops_for` table is consulted; if the mob's death position is within 8 blocks of a `SALT_LICK` (per `world.salt_licks` snapshot) **and** the mob is affected-species, the primary product drop is incremented by 1 (extra Leather/Wool, or extra Milk/Eggs for breeding species via a new "primary product" mapping table per species).

**Block discovery.** `World` gains an `AHashSet<(i32, i32, i32)> salt_licks` side-table — populated at place time, drained at break time, and rebuilt on load via a single full-world scan in `WorldSave::load_finalise` (cheap; one pass of loaded chunks). Mirrors the existing `village_anchors` / `brigand_hideouts` shape.

Pure-helper test surface:
- Affected-species table is exact (5 yes, 7 explicitly no).
- `regen_multiplier_at_pos` returns 2.0 inside the radius, 1.0 outside, on the boundary, and with no licks placed.
- `wander_bias_for_salt_lick` returns the lick direction within 16 blocks, falls back to neutral outside.
- Drop-bonus arm fires exactly once per kill (no double-counting if multiple licks are in range).

### 4. Salt Path + minimal snowfall

New module `snowfall.rs`. Two halves: the **path placement** (player-driven) and the **snowfall painter** (world-driven).

**Path placement** (block-interaction path, lives in `block_interact.rs`):

- Right-click Salt material on `GRASS` or `DIRT` top face → converts that block to `SALT_PATH`; consumes 1 Salt from the hotbar stack.
- Right-click Salt material on a `SNOW` block → places `SALT_PATH` at the SNOW position (snow is melted into the path); consumes 1 Salt.
- Pure helper `target_block_accepts_salt_path(BlockId) -> bool` returning `true` for `GRASS | DIRT | SNOW`.

**Snowfall painter** (called every 6 000 ticks ≈ 5 in-game minutes from `GameServer::tick` + the single-player `GameState::tick`):

- For each loaded chunk whose `BiomeGenerator::biome_at(centre)` is `SnowyTundra`:
  - Pick 1 random column inside the chunk via a deterministic `(world_seed ^ chunk_key ^ current_tick / 6000)` hash.
  - Look up the surface block at `terrain_height(wx, wz)`.
  - If the surface is `GRASS` or `DIRT`, place `SNOW` at `surface + 1` (replacing the AIR above). Skip if already `SNOW`, `SALT_PATH`, or anything else.
- Pure helper `snowfall_attempt_for_chunk(seed, chunk_key, current_tick) -> Option<(i32, i32)>` returning the picked column (or `None` on a roll-skip via the seed).

This is intentionally NOT a weather system. No wind, no clouds, no per-frame particle effects. Snow is just slowly drifted in over time, at a rate Axolittle will perceive as "after a session in the tundra you can see snow has grown". Speed is tunable via `SNOWFALL_PERIOD_TICKS` (default 6 000; bumped by `/time speed N` engine command).

### 5. Salt Lamp

Pure decoration; no module of its own (lives in `block.rs` BlockDef table + `lighting.rs` light-emission table).

- `light_emission(SALT_LAMP) = 14` — matches `TORCH` exactly (so `lighting.rs` BFS Just Works).
- `light_absorption(SALT_LAMP) = 0` — passes light through (matches torch).
- `solid = true`, occupies a full block (unlike torch's small-cube). Placement gate via existing block-place path; floor-only via a pure helper `salt_lamp_floor_supported(world, [x,y,z]) -> bool` that checks the block below is `solid`.
- Texture as above.
- Recipe: cross 4 Salt + 1 Stick centre → 1 SALT_LAMP.

### 6. Recipes

All routed through `match_recipe` arms, UK English names throughout:

| # | Pattern (rows × cols) | Inputs | Output |
|---|---|---|---|
| 1 | 3×3 | 9 × `Salt` | 1 × `SALT_BLOCK` |
| 2 | 1×1 | 1 × `SALT_BLOCK` | 9 × `Salt` |
| 3 | Cross (3×3, corners empty) | 4 × `Salt` + 1 × `Stick` (centre) | 1 × `SALT_LAMP` |
| 4 | 2×1 vertical | 1 × `SALT_BLOCK` (top) + 1 × `Cobblestone` (bottom) | 1 × `SALT_LICK` |
| 5–10 | 1×2 horizontal | 1 × `Salt` + 1 × raw meat (each of `RawBeef`, `RawPorkchop`, `RawMutton`, `RawChicken`, `RawRabbit`, `RawNostrichMeat`) | 1 × `SaltCured X` (6 recipes) |
| 11–19 | 1×2 horizontal | 1 × `Salt` + 1 × cooked staple (each of `Bread`, `BakedPotato`, `BakedCarrot`, `BakedCorn`, `CookedBeef`, `CookedPorkchop`, `CookedMutton`, `CookedChicken`, `CookedRabbit`) | 1 × `Seasoned X` (9 recipes) |

**Cured / Seasoned variants** add 15 new `MaterialId` variants: 6 `SaltCured*` (one per raw meat: Beef/Porkchop/Mutton/Chicken/Rabbit/NostrichMeat) and 9 `Seasoned*` (one per cooked staple: Bread/BakedPotato/BakedCarrot/BakedCorn + 5 cooked meats — Beef/Porkchop/Mutton/Chicken/Rabbit; Nostrich has no cooked variant in the current engine, only NostrichOmelette). Each has `food_value = base + 1`, `trade_value = base + 1`. **Cured X is the end product** — it cannot be further cooked into a "Cured Cooked X" variant (capped to keep the variant explosion bounded; cooked-then-seasoned is the other ladder). The variant count matches the precedent set by Spec 12 T1.5 (Bread/BakedPotato/BakedCarrot etc.).

**Drop bonus** is keyed off a per-species `salt_lick_primary_drop(MobType) -> MaterialId` table: Cow → Leather, Sheep → Wool, Pig → RawPorkchop, Horse → Leather, Goat → RawMutton. Defined in `salt_lick.rs` as pure data; one row per affected species.

### 7. Snowfall + path-salt cross-tests

Integration tests live in `test_integration/salt.rs`:

- `snowfall_drifts_over_session` — set `SNOWFALL_PERIOD_TICKS = 200` for test; place 5×5 grass-tile patch in a `SnowyTundra` chunk; advance 4 000 ticks; assert ≥ 1 SNOW block has appeared.
- `salt_path_blocks_snowfall` — same patch but all 25 tiles converted to SALT_PATH first; advance 10 000 ticks; assert 0 new SNOW blocks.
- `salt_path_melts_existing_snow` — patch covered in SNOW; right-click Salt on each; assert each becomes SALT_PATH and Salt stack decrements.
- `salt_lick_increases_cow_regen` — place Cow at half HP next to a SALT_LICK; tick `N`; assert regen rate is 2× the no-lick baseline.
- `salt_lick_grants_drop_bonus` — place Cow next to SALT_LICK; kill; assert Leather drop count is base + 1.
- `salt_lick_no_bonus_outside_radius` — place Cow 9 blocks away; kill; assert standard drop count.

### 8. Save / load

- `World.salt_licks: AHashSet<(i32, i32, i32)>` populated at place-time, drained at break-time, rebuilt on load via `rebuild_salt_lick_index()` in `WorldSave::load_finalise`. `#[serde(skip)]` (the block placement IS the canonical state; the index is a derived cache).
- New block IDs all serialise as `u16` per the existing positional bincode contract.
- New material IDs all serialise as positional u16 enum discriminants. Variants are append-only as the project's standing rule.

## Out of scope (deferred to v2 or follow-on specs)

- **Salt-pan / sea-salt evaporation** — second source path; v2 if mining alone proves too limiting.
- **Breeding system** — Salt Lick attracts livestock but does not pair-bond them into offspring. Breeding is its own Farming T2 spec.
- **Seasonal weather** — the snowfall painter is constant-rate in `SnowyTundra` chunks; no winter cycle, no seasons. Real weather is its own foundation spec post-alpha.
- **Wall-mounted Salt Lamp** — floor-only for v1. Wall-mount variant is one more BlockId + place-direction logic; defer until kids ask.
- **Salt as a wolf/bear deterrent** — the user's brief didn't ask for it; carnivores are unaffected by Salt Lick.
- **Custom salt-lamp light colour (warm amber tint)** — would need shader work; the texture sells the warm feel without it.
- **Snowball item from mining `SNOW`** — would re-open the question "is snow a resource or just terrain?"; defer until path-salt has had a playtest pass.
- **Salt-cured + Seasoned compatibility with Vendor Block plan trades** — variants are stack-eligible for vendor inventory automatically (the Vendor Block reads `MaterialId`/`Item` generically) so no Vendor change needed; v2 may want a "premium goods" listing badge to highlight the food-value tier.
