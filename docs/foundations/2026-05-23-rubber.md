# Rubber — tapped trees, slingshot, boots, eraser, cable data-laydown

**Status:** Phases 2–12 DELIVERED 2026-05-23 on `feat/rubber`. Phase 13 = Axolittle playtest gate (open).
**Branch:** `feat/rubber` off `main`.
**Trigger:** Axolittle's call (2026-05-23, post-Salt) — add a rubber tree to the engine. Rubber drives a slingshot + boots + Plan Tile eraser; copper-rubber cables ride along as data-laydown for the future electricity system.

---

## TL;DR

A 7th `WoodSpecies::Rubber` joins the existing six. Rubber trees generate in Jungle biome; their wood is timber-only when felled. Rubber itself comes from **tapping the living tree** with an empty bucket — a `RUBBER_LOG` converts to `RUBBER_LOG_TAPPED` on tap, ticks back to `RUBBER_LOG` after a 24 000-tick (~1 in-game day) cooldown. The player must choose between ongoing tapping or one-shot timber.

Rubber drives four uses:
- **Slingshot** + **Rubber Ball** ammo — a low-tier ranged tool that stuns passive mobs on hit (kid-readable, non-lethal).
- **Rubber Boots** — new `ArmourMaterial::Rubber`, boots slot only; sprint-speed multiplier doubles while equipped.
- **Eraser** — a new tool that converts `PLAN_TILE` blocks back to `PapyrusSheet` (partial reclaim) and wipes captured cells from Plan items.
- **CopperCable** — pure data laydown for the future electricity foundation spec.

4 new BlockIds (120–123), 6 new MaterialIds (`Rubber`, `RubberSapling`, `RubberBall`, `CopperCable`, plus the cured-economy parallel skipped here — see *Out of scope*), 1 new `ToolType::Slingshot`, 1 new `ToolType::Eraser`, 1 new `ArmourMaterial::Rubber`, ~9 new recipes, ~1 800 LOC including tests. PROTOCOL_VERSION 29 → 30. Two new modules: `rubber.rs` (tap state machine + cooldown index helpers) and `slingshot.rs` (stun-on-hit projectile arm).

Independent of every open spec — no shared files with Specs 1 (engine Signet auth) or 2 (HostedServer routing). Parallelisable with anything currently in flight.

---

## Why this lives here

- **First "infrastructure-is-alive" mechanic.** Rubber trees are the only resource in the engine where keeping the source alive matters. Felling = wood; tapping = rubber. The decision is real and player-legible, and it teaches sustainability in concrete-rules form. Engine-generic — the same shape lifts to any cross-game "renewable resource from a living entity" pattern (sap, milk, honey lift cleanly).
- **Pulls Jungle biome from "exotic terrain" to "destination biome".** Jungle currently has no unique resource. Rubber trees give a reason to seek the biome out, mirroring how Salt pulled SnowyTundra/Mountains from "scenery" to "interactive".
- **Foundation for electricity post-alpha.** CopperCable arrives as a typed material with a real recipe today, so the future electricity spec can wire mechanics around an existing item instead of forking the material registry from scratch.
- **Closes a Plan-Tile economy loop.** Spec 24's Plan Tile is currently one-way (paper → tile → plan; no recovery if the player wants to remake a plan). The Eraser tool lets a player reclaim 1 PapyrusSheet per tile, making mistakes cheap.

## What this PR ships

### 1. `WoodSpecies::Rubber` + 4 new BlockIds

Appended to `WoodSpecies` after `DarkOak`. Per-species blocks at ids 120–123:

| ID | Block | Mining behaviour | Notes |
|---|---|---|---|
| 120 | `RUBBER_LOG` | Drops 1 RUBBER_LOG (timber only). Tappable via right-click with empty Bucket. | Pale amber log texture; subtle vertical bark grain. |
| 121 | `RUBBER_PLANKS` | Drops itself. | Joins `is_any_planks` so plank-generic recipes still resolve. |
| 122 | `RUBBER_LEAVES` | Drops `RubberSapling` at 5 % per the existing leaf-drop pattern. | Slightly darker green than oak leaves; lobed shape baked into the texture. |
| 123 | `RUBBER_LOG_TAPPED` | Drops 1 RUBBER_LOG (timber only — cooldown state is lost). | RUBBER_LOG texture + a small spout + cup overlay on one face. Ticks back to RUBBER_LOG after 24 000 ticks. |

Each block uses standard species mechanics (planks craft 1 log → 4 planks; saplings plant on dirt/grass; leaves decay). No mining-tier change vs Oak — wood tier with any axe.

### 2. New tap state machine — `rubber.rs`

New module holding the pure helpers + the tick driver. Mirrors the `salt_lick.rs` + `snowfall.rs` shape:

- `is_tappable(BlockId) -> bool` — returns true only for `RUBBER_LOG`.
- `apply_tap(world, pos, current_tick) -> bool` — converts `RUBBER_LOG` at `pos` to `RUBBER_LOG_TAPPED`, stamps the cooldown index. Returns true on success, false if the position isn't a RUBBER_LOG or is already tapped.
- `tick_rubber_cooldowns(world, current_tick) -> u32` — walks `World.tapped_rubber_logs`, finds entries whose cooldown has expired, restores them to `RUBBER_LOG`, drops the entry. Returns the count of restorations.
- `TAP_COOLDOWN_TICKS = 24_000` constant (same as the brigand hideout replenisher).

`World.tapped_rubber_logs: AHashMap<(i32,i32,i32), u64>` (position → tick when tapped). `#[serde(skip)]` — rebuilt on load by scanning for `RUBBER_LOG_TAPPED` blocks (matches the `salt_licks` precedent; the cooldown picks up from `load_tick` so the player isn't locked out across a save-reload).

### 3. Right-click handler in `block_interact` / `game_loop`

When the held item is an empty Bucket and the targeted block is `RUBBER_LOG`:

1. Bucket stays in the hotbar (collection tool, not a container).
2. 1 `Rubber` material added to the player's inventory; if the inventory is full, the rubber spawns as an item-entity at the tap site.
3. `apply_tap(world, pos, current_tick)` flips the block + stamps the cooldown.
4. `pending_block_changes` + `rebuild_chunk_at` per the existing convention.
5. Toast (single-player only): "Tapped — rubber will be ready again at dawn."

The handler sits next to the existing salt-on-grass arm in `game_loop.rs`.

### 4. New materials

| Material | Notes |
|---|---|
| `Rubber` | Tier 0 raw drop. Crafting ingredient for everything below. |
| `RubberSapling` | Tier 0 (matches every other sapling). Plants on dirt/grass like the existing 6 saplings. Joins `commands/builtins/give.rs`. |
| `RubberBall` | Tier 1 — slingshot ammo. Recipe: 1 Rubber → 4 Balls. |
| `CopperCable` | Tier 2 (Copper Ingot + Rubber processing). Recipe: 4 Copper Ingot row + 1 Rubber centred above → 4 Cables. No gameplay effect in v1; consumed by future electricity spec. |

`Item::name`, colour, food_value (None — none are edible), trade_value, complexity_tier arms all updated.

### 5. Slingshot tool — `slingshot.rs`

New module with the projectile-arm helpers, mirroring the existing arrow path in `entity.rs`:

- `ToolType::Slingshot` appended to the existing tool-type enum. Single Wood-tier only (matches Bow + Flint and Steel — the cross-tier ladder lives only on the four standard tools).
- Recipe: 3×3 Y-fork shape. `Stick / Rubber / Stick` on top row + empty / `Stick` / empty in the middle + all-empty bottom (or `1 Stick + 2 Sticks vertical + 1 Rubber centred` — exact pattern picked at implementation; the test will lock it in).
- Active-use: hold left-click to charge (matches Bow's draw + release flow); on release, spawn a Rubber Ball projectile.
- Pure helpers:
  - `slingshot_damage(charge_ticks)` → 1.0 + (charge_ticks as f32 / 20.0).min(2.0); damage caps at 3.
  - `slingshot_stun_ticks(target_kind, charge_ticks)` → 20 for passive/neutral mob targets with at least half-charge; 0 for hostile-aggro brigands (they shrug it off) and 0 for players.
- On-hit handler in `combat.rs`: if `stun_ticks > 0` and the target is in `AiState::Idle | Wander`, set `AiState::Wander { timer: stun_ticks }` (forces a brief stop). If the mob is in `Chase`, no effect — slingshot doesn't break a real attack lock.

### 6. Rubber Boots — `ArmourMaterial::Rubber`

- New `ArmourMaterial::Rubber` variant. Existing armour-point table extended:

| Slot | Leather | Iron | Chainmail | Diamond | Satori | Rubber |
|---|---|---|---|---|---|---|
| Helmet | 1 | 2 | 2 | 3 | 4 | – |
| Chestplate | 2 | 4 | 4 | 6 | 8 | – |
| Leggings | 2 | 3 | 3 | 5 | 6 | – |
| Boots | 1 | 2 | 2 | 3 | 4 | **2** |

Rubber appears only in the Boots row. Crafting any non-Boots slot from Rubber returns `None` from the recipe-match arm (no Rubber Chestplate). Recipe: same shape as other boots ("`M . M / M . M`" in a 3×2 / 3×3 grid).

Behaviour: while a player has `ArmourMaterial::Rubber` boots equipped, their sprint-speed multiplier is doubled. The existing `combat.rs::sprinting: bool` already gates the multiplier; this adds a small lookup at the multiplier site.

Pure helper `sprint_multiplier_for(player_slot) -> f32`: returns `2.0` if the player's boots slot holds Rubber, else `1.0`. Wired into the physics/movement tick (the exact site lives in `game_loop.rs` next to the existing `sprinting` check).

### 7. Eraser tool — `ToolType::Eraser`

- New `ToolType::Eraser` appended to the existing tool-type enum. Single Wood-tier (durability 32 — matches Flint and Steel + Shears).
- Recipe: 1 Rubber in a 1×1 grid → 1 Eraser. (The simplest single-craft yield — matches how Bonemeal / String / Bone reverse-recipes work.)
- Right-click on a `PLAN_TILE` block → mines the tile, returns 1 `PapyrusSheet` to inventory, decrements eraser durability by 1.
- Right-click on a Plan item in inventory (via the inventory explorer's "use" affordance) → resets the Plan to debug state (clears `captured_cells`), decrements eraser durability by 4. (Higher cost — wiping a Plan is a bigger action than reclaiming a single tile.)
- Pure helpers:
  - `eraser_reclaim_tile(block_id) -> Option<MaterialId>`: returns `Some(PapyrusSheet)` for `PLAN_TILE`, `None` otherwise.
  - `eraser_wipe_plan(&mut PlanData)`: clears `captured_cells` + bumps a `revision` counter so listeners can react if needed.

### 8. Recipes (9 new)

| # | Pattern | Inputs | Output |
|---|---|---|---|
| 1 | 1×1 | 1 × `RUBBER_LOG` | 4 × `RUBBER_PLANKS` |
| 2 | 1×1 | 1 × `RubberSapling` (place-on-grass) | plants the tree |
| 3 | 3×3 Y-fork | `S . S` top + `. R .` middle + `. S .` bottom (3 Sticks + 1 Rubber) | 1 × Slingshot |
| 4 | 1×1 | 1 × Rubber | 4 × RubberBall |
| 5 | 3×2 boot | `R . R / R . R` (4 Rubber, boot-shape — same pattern as Leather Boots) | 1 × Rubber Boots |
| 6 | 1×1 | 1 × Rubber | 1 × Eraser tool |
| 7 | 1×3 horizontal | `C R C` (2 Copper Ingot + 1 Rubber centre) | 2 × CopperCable |
| 8 | Existing planks-to-sticks (already supports any-planks) | 2 RUBBER_PLANKS vertical | 4 Sticks |
| 9 | 3×3 crafting-table from any-planks | already supports rubber planks via `is_any_planks` | Crafting Table |

Recipes 8 + 9 are no-code-change consequences of `is_any_planks` already covering the new species — they're listed here for completeness, not as new arms. **5 new crafting arms** total (Slingshot, RubberBall, Rubber Boots, Eraser, CopperCable) + plank-from-log (recipe 1) gets a new mining-arm reference; sapling-to-tree (recipe 2) goes through the existing sapling-place path. So **6 net new code paths**.

### 9. Save / load

- All 4 new BlockIds + 4 new MaterialIds serialise as positional u16 enum appends (no save-shape change).
- `World.tapped_rubber_logs` is `#[serde(skip)]` and rebuilt by walking chunks at load-time for `RUBBER_LOG_TAPPED` blocks. The cooldown clock continues from `current_tick` at load (i.e., a tapped tree saved-and-reloaded keeps ~1 day's wait from the reload tick — players don't get an instant ready-again just by reloading). This matches the salt_licks rebuild precedent.
- PROTOCOL_VERSION 29 → 30 with history note.

## Acceptance criteria

- `check.sh` ALL GREEN at the end of each phase commit.
- ~25 net new tests (3–6 per phase).
- PROTOCOL_VERSION bumped exactly once (Phase 2) with the history-line note.
- Save/load round-trip — a world with 5 tapped rubber logs survives a save+load cycle with the cooldowns preserved (continuing from `current_tick` post-load), per the existing `save_load.rs` test pattern extended with a rubber scenario.
- Mining a `RUBBER_LOG` (felled, no tap) produces zero Rubber — the timber-only path is enforced.
- Mining a `RUBBER_LOG_TAPPED` produces 1 RUBBER_LOG (timber) and removes the cooldown index entry.
- Right-click empty Bucket on a freshly-spawned `RUBBER_LOG` produces 1 Rubber AND converts the block to `RUBBER_LOG_TAPPED`. A second right-click on the same `RUBBER_LOG_TAPPED` produces no Rubber (already tapped). After 24 000 ticks, the cooldown driver flips the block back to `RUBBER_LOG`.
- Slingshot fires a Rubber Ball entity that travels in a ballistic arc (matches the existing Arrow physics, lower starting velocity).
- Slingshot hit on a Cow at half-charge sets `AiState::Wander { timer: 20 }` regardless of the cow's prior state (was Idle).
- Slingshot hit on a Brigand at any charge does not interrupt their Chase state.
- Equipping Rubber Boots doubles the sprint-speed multiplier (visible at playtest: a kid can feel they're faster).
- Eraser right-click on a `PLAN_TILE` returns 1 PapyrusSheet + decrements eraser durability.

## Out of scope (deferred to v2 or follow-on specs)

- **Electricity** — CopperCable arrives as a typed material with a real recipe but has zero gameplay effect in v1. The electricity foundation spec is post-alpha; this spec just lays the bridge.
- **Stamina / endurance system** — Rubber Boots doubles the existing sprint-speed multiplier; no new stamina meter or sprint-duration mechanic. A real stamina system is its own foundation spec.
- **Bouncy rubber blocks** — the "rubber should bounce" trope considered + REJECTED for v1. Bounce physics is a meaningful new system; Rubber Planks are visually warm-amber but mechanically identical to Oak.
- **Rubber-as-string-substitute** — considered + REJECTED. Would step on HP-1's wool → string economy. Rubber and String stay in distinct lanes.
- **Latex Collector block** — a placed bowl at the base of a rubber tree that catches rubber over time without a right-click was considered + DEFERRED. Adds another block; v1 stays right-click-with-bucket because that's the smallest motion.
- **Vulcanised Rubber** — a higher-tier processed variant (Rubber + Sulphur → Vulcanised Rubber, with stronger boots / better cables) is a natural v2 if Axo wants tiering on rubber items.
- **Full Rubber armour set** — only Boots ship in v1. Helmet / Chestplate / Leggings stay out so the material has one clear purpose.
- **Slingshot Stone ammo** — Rubber Balls are the canonical ammo; rocks-as-ammo would need a "any small block" projectile path that doesn't currently exist.
