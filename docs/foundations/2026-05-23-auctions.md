# Auctions (v1) — time-limited price discovery

**Status:** Phases 2-10 DELIVERED 2026-05-23 on `feat/auctions`. Phase N = Axolittle playtest gate (open).
**Branch:** `feat/auctions` off `main`.
**Trigger:** Goal-driven solo dev cycle, Round 7. Owner steered to it. From `docs/vision/economies-long-run.md` §4.3 — "Auctions (T3)". The first **time-pressured** market primitive: lot + reserve + countdown + bidding + anti-snipe. The Lightning HOLD-invoice escrow is BRIDGE'd (accounting-only on alpha, like every sats path).

---

## TL;DR

A new **Auction Block** (id 129) with a timed block-entity (`BlockEntityData::Auction(AuctionData)`):

1. **Owner configures + starts** — right-click your own (un-started) auction → set the lot (from the held item), a reserve price, and a duration; starting stamps `deadline_tick = tick_counter + duration`.
2. **Anyone bids** — right-click an active auction → place a bid above `high_bid + MIN_INCREMENT`. The current high bid + bidder + time-left show in the dialog.
3. **Anti-snipe** — a bid landing within `ANTI_SNIPE_WINDOW` of the deadline pushes the deadline out by `ANTI_SNIPE_EXTEND` (no last-second steals).
4. **Settlement at expiry** — a per-tick driver (`tick_auctions`, using `tick_counter` monotonic — never `world_time`) settles when the deadline passes: if `high_bid >= reserve` and there's a bidder, the lot is delivered to the winner (as an `ItemEntity` at the block, so an offline/full winner still gets it) and the proceeds credit the owner's `escrow_sats` (drained via the owner dialog, mirroring Vendor/Tip Jar). Below reserve → the lot returns to the owner.

**Escrow is notional on alpha** (per the Round-7 audit): there's no real wallet, so "hold a bid / refund on outbid" is just overwriting `high_bid`/`high_bidder`. A `held_sats` field records the notional hold for the future Lightning path. **BRIDGE:** real HOLD-invoice escrow + refunds land when Sentinel D-003 reverses (same gate as all sats settlement).

1 new BlockId (129), 1 new MaterialId (`AuctionBlockItem`), 1 new `BlockEntityData::Auction` variant, 1 new module (`auction.rs` — AuctionData + pure bid/settle helpers), 1 new UI (`auction_ui.rs` — configure + bid + status views), 1 recipe, 1 texture, tick-driver in `GameState::tick`. PROTOCOL_VERSION 35 → 36. **Estimated ~1 100 LOC including tests.**

---

## Why this lives here

- **First time-pressured market.** Vendor Blocks (fixed price) + Market Hubs (discovery) are static. An auction creates a *moment* — a countdown, rising bids, the anti-snipe tension. That's the first piece of market drama, and it's how price discovery actually happens for rare/unique items (a Satori, a one-off Plan).
- **Composes the substrate built this session** — block-entity timed state (Furnace pattern), settlement (Vendor pattern), the LocalPlayer/Npub owner model, the `ItemEntity` drop for offline delivery (raid-loot pattern). No new economic primitive type, just a new *time* dimension.
- **Cross-game lifts** — timed-auction + anti-snipe + deadline-settlement is engine-generic.
- **Foundation for Tournaments (7.2)** which reuse bracket + bid/stake + spectator-tip patterns.

## What v1 ships

### 1. `AUCTION_BLOCK` (id 129)
Owner-only break (anti-grief). Breaking an un-settled auction returns the lot to the owner (spawn_item) + clears the block-entity. Recipe: a distinct shape — e.g. a gold-nugget-or-iron over a Vendor-ish base; verify no collision (recipe space is dense — likely a 3-tall column `iron / plank / iron` or similar distinct pattern).

### 2. `auction.rs` — AuctionData + pure helpers
```rust
pub const MIN_BID_INCREMENT: u64 = 1;
pub const ANTI_SNIPE_WINDOW_TICKS: u64 = 600;   // 30s @ 20 TPS
pub const ANTI_SNIPE_EXTEND_TICKS: u64 = 600;
pub const DEFAULT_DURATION_TICKS: u64 = 12_000;  // 10 min

pub enum AuctionOwner { LocalPlayer(usize), Npub(String) }   // converge per [[project_economy_block_owner_convergence]]

pub struct AuctionData {
    pub owner: AuctionOwner,
    pub lot: Option<ItemStack>,       // None until configured
    pub reserve_sats: u64,
    pub high_bid: u64,
    pub high_bidder: Option<usize>,   // pidx (alpha); Npub later
    pub held_sats: u64,               // notional hold (BRIDGE)
    pub deadline_tick: u64,           // absolute tick_counter; 0 = not started
    pub started: bool,
    pub settled: bool,
    pub escrow_sats: u64,             // owner proceeds after settle (Withdraw)
}

/// Result of a bid attempt — pure.
pub enum BidOutcome { Accepted { new_deadline: u64 }, TooLow, NotActive, OwnerCannotBid }
pub fn try_bid(data: &mut AuctionData, bidder_pidx: usize, amount: u64, now_tick: u64) -> BidOutcome;

/// Should this auction settle now? (started, not settled, deadline passed.)
pub fn should_settle(data: &AuctionData, now_tick: u64) -> bool;

/// Settlement decision — pure; caller performs the item/sats side-effects.
pub enum SettleResult {
    SoldTo { winner_pidx: usize, proceeds: u64 },  // lot → winner, proceeds → owner escrow
    Unsold,                                         // below reserve / no bids → lot → owner
}
pub fn settle(data: &mut AuctionData) -> SettleResult;

pub fn is_local_owner(owner: &AuctionOwner, pidx: usize) -> bool;
pub fn time_left_ticks(data: &AuctionData, now_tick: u64) -> u64;
```

### 3. `BlockEntityData::Auction(AuctionData)` + World accessors + WorldSave round-trip
`auction_at` / `auction_at_mut` / `iter_auctions`; `WorldSave.auctions: Vec<SavedAuction>` (`#[serde(default)]`). AuctionData is serde-able (ItemStack already is).

### 4. Tick driver `tick_auctions(world, ecs, tick_counter)`
Snapshot-keys-then-mutate (per audit): collect auction positions → for each, if `should_settle`, call `settle` → perform the side-effects (deliver lot via `entity::spawn_item` at the block; credit owner `escrow_sats` via `apply_sats_payout(proceeds, PayoutKind::VendorSale, …)`). `None => continue` guard for blocks mined mid-tick. Wired into `GameState::tick` (single-player path; multiplayer settlement shares the Furnace single-player-only caveat — acceptable for alpha, documented).

### 5. `auction_ui.rs` — three views
- **Owner, un-started**: set lot (from held item), reserve +/- , duration picker → Start.
- **Owner, active/settled**: status (high bid, time left) + Withdraw proceeds after settle.
- **Bidder**: current high bid, time left, a Bid button (+ MIN_INCREMENT presets) gated by Charter + bitcoin_enabled (barter-auctions are a v2 thought).

### 6. `PayoutKind::AuctionSale` (or reuse VendorSale)
v1 reuses `PayoutKind::VendorSale` for the proceeds payout (an auction sale IS a vendor-style sale) to avoid enum churn — OR adds `AuctionSale` for cleaner analytics. Decide at build (leaning reuse VendorSale + a comment).

### 7. `/give` aliases (`auction`, `auction_block`). PROTOCOL 35 → 36 + handshake history.

### 8. Tests
Pure (`auction.rs`): try_bid accept/too-low/not-active/owner-cannot-bid; anti-snipe extends deadline within window, doesn't outside; should_settle gating; settle sold-vs-unsold (reserve boundary); time_left. Integration (`test_integration/auction.rs`): configure→start→bid→expiry-settle delivers lot + credits escrow; below-reserve returns lot; save round-trip; owner-break returns lot.

## Out of scope (v2)
- **Real Lightning HOLD-invoice escrow + refunds** — notional on alpha (BRIDGE). The `held_sats` field is the laydown.
- **Barter auctions** (lot-for-lot, no sats) — v2.
- **Multiple lots / lot stacks beyond one ItemStack** — v1 = single ItemStack lot.
- **Multiplayer settlement** — `tick_auctions` in `GameState::tick` only (Furnace caveat). Server-path settlement is v2 with the dual-sim cleanup.
- **Bid history / bidder list UI** — v1 shows current high only.
- **Buy-it-now price** — v2.

---

## Known limitations (BRIDGEs)
1. **Escrow + bids notional** — no real wallet on alpha; `apply_sats_payout` is accounting-only. `held_sats` records the notional hold for the future LN path. BRIDGE comment in `auction.rs`.
2. **`AuctionOwner::LocalPlayer(pidx)`** — same split-screen→solo-reload edge case as Vendor/Tip Jar/Plot/Market; converge to Npub together per [[project_economy_block_owner_convergence]]. Add Auction to that memory on completion.
3. **Single-player settlement only** — `tick_auctions` lives in `GameState::tick` (Furnace precedent); multiplayer expiry-settle is v2.
4. **`high_bidder` is a pidx** — fine for alpha solo/split-screen; the offline-winner delivery uses `spawn_item` at the block so it doesn't depend on the winner being a live slot.

## Acceptance criteria (solo)
- AUCTION_BLOCK craftable/placeable; placing stamps owner.
- Owner configures lot + reserve + duration + starts; deadline = tick_counter + duration.
- A non-owner bid above the increment is accepted + shown; a too-low bid is refused.
- A bid in the final window extends the deadline (anti-snipe).
- At expiry: ≥reserve → lot spawns at the block for the winner + owner escrow credited; <reserve → lot returns to owner.
- Owner-break before settle returns the lot.
- Save/reload round-trips auction state.
- `check.sh` ALL GREEN. PROTOCOL 36.
