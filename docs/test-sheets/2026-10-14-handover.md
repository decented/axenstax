## A hosts, B joins

- [ ] A creates/opens a supported world and hosts online. Copy its original
      invitation once and keep the exact string for all later reconnects.
- [ ] B joins using that string. A and B visibly have distinct bags: put a
      recognisable stack/tool in different slots and wear different armour.
- [ ] Make a loaded block edit and another edit far enough away to unload its
      chunk; put items in a chest. Include supported authored/attachment/Plan
      state and a source-owned wolf/cart if available in this accepted build.
- [ ] Ordinary mining/crafting/eating/container use still works. Missing
      agreement, unsupported personal/ownership state or outstanding obligations
      produce an honest refusal before retirement. Active quests remain refused
      until their complete handover carrier is accepted; do not infer support.

## First handover: A→B

- [ ] A chooses “Hand this world to …” for the actual signed participant B.
      B sees the correct world, source name/npub, persisted-checkpoint scope and
      storage-on-B disclosure, with explicit Accept/Cancel controls.
- [ ] Cancel once at the initial consent screen, before bearer disclosure.
      A/B return to working play;
      no queued chest click, crafting action or placement happens twice.
- [ ] Begin again and accept. Gameplay pauses while the copy moves; rendering
      and transfer controls remain usable. Prepared data is not playable early.
- [ ] B opens the activated world through the lobby. Its own bag/grid/cursor,
      armour, vitals and supported progress are present. A's bag is not donated.
      Loaded/unloaded edits, chest, authored history and supported saved entities
      are preserved. Private Plan bodies resolve only from the owner's own store;
      unknown bodies remain explicit markers.
- [ ] A's original world folder remains retired. Its separate retained copy is
      listed under a distinct identity/folder, keeps A's own state and authored
      history, and has fresh publication with inherited opt-ins disabled.
- [ ] In the retained copy, change A's bag/chest and save/reopen; consume an item
      and confirm the old frozen item does not return. Autosave/discard selects
      the matching bag and chest, without a duplicate on withdrawal.
- [ ] Deliberately hosting that fresh retained copy is an ordinary separate
      action. Its fresh link works for admitted B; the old original invitation
      cannot enter the retained copy through a contact shortcut.
